# Senaの言葉を判断原則として残す

この文書は、Senaの発言を単なるコピー候補ではなく、企画・UI・実装の判断原則として扱うための共通ルールです。

## 記録単位

重要な発言を残すときは、次の4点を分けます。

1. 原文: 要約せず、そのまま保存する。
2. 決定: 何を採用したかを一文で明示する。
3. 実装への含意: 訴求順、UI、機能、運用へどう反映するかを書く。
4. 置き換え対象: 古い解釈のうち、何が無効になったかを書く。

## 判断ルール

- 最新の明示的な訂正は、それと矛盾する古い解釈を置き換えます。
- 発言の日付だけで機械的に上書きせず、本人が決定または訂正した内容だけを採用します。
- 面談、ツール、交流会などの手段を、本人が語った本質より上位へ勝手に持ち上げません。
- 公開文面は運営側の機能一覧ではなく、参加者が得る変化の順に組み立てます。
- 原文とCodexの解釈を混ぜません。解釈が変わっても原文は残します。
